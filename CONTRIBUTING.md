# Contributing

Use Python 3.11+ and run commands from the repository root:

```bash
uv sync --locked --extra dev
uv run pytest -q
uv run learning-support demo --no-ui
```

Describe the problem, expected behavior and a small synthetic example in an issue before major scope changes. Pull requests should explain the final behavior, include appropriate boundary checks and state validation actually run.

Preserve first-valid attempts, cutoff-time isolation, assigned-task denominators, missing values, comparable strata and explicit evidence limitations. Keep abilities separate from the two-domain grouping. Rule/threshold changes require versioning and a reason; do not invent educational effectiveness evidence.

Do not commit real student data, secrets, databases, generated CSV files or local execution logs. Do not submit private application documents. Generated reports belong outside the source tree; the curated example is deliberately synthetic.

The current supported workflow is a source checkout with an editable installation. Changes to deployment, authentic student data or predictive modeling require a separately reviewed design.
